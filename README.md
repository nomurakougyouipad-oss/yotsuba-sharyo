# 社用車管理アプリ — Claude Code 引き渡し資料

作成日: 2026-09-26
会社: よつば建設工業
参考: 消防車製作管理アプリ（fire-seisaku）と同じ技術スタック・同じ進め方で作る

---

## 1. 目的（ひとことで）

会社の車（6〜15台）について、**「どの車が空いていて、誰がどの現場で使っていて、いつ車検か」** を
現場の人はスマホで、事務所はPCで、いつでも同じ情報で見られるようにする。

GPS・位置追跡は **やらない**（検討の結果、見送り）。
「空き車両がどの駐車場にあるか」は、返却時に駐車場を3つのボタンから選んで記録する方式で代用する。

## 3. 技術スタック（消防車アプリと同じ）

- フロント: **HTML / CSS / Vanilla JS**（フレームワーク不使用、単一ページ）
- ホスティング: **GitHub Pages**
- DB: **Firebase Firestore**（リアルタイム同期）
- 写真: **Firebase Storage**（アップロード時にブラウザ側で自動リサイズ、長辺1280px程度・JPEG）
- 認証: **Firebase 匿名認証**（消防車アプリと同じ。ユーザー登録なし）
- PWA対応（ホーム画面に追加できる。manifest + service worker）
- フォント: Zen Kaku Gothic New（Google Fonts）
- Firebaseプロジェクト: **yotsuba-sharyo**（作成済み・Blazeプラン）。設定は同梱の `firebase-config.js` を使う（SDKはCDN v12.19.0、`<script type="module">`）
  - 作成済み: Firestore（nam5・Standard・テストモード・毎週月曜バックアップ）/ Storage（US-EAST1・テストモード）/ 匿名認証 有効 / Webアプリ yotsuba-sharyo-web 登録済み
  - テストモードは30日で失効するので、段階1で firestore.rules / storage.rules を必ず書くこと
- セキュリティルール（firestore.rules / storage.rules）も書くこと。テストモードのまま公開しない。

## 4. 使う人と使い方

| 誰 | 端末 | やること |
|---|---|---|
| 現場担当者（数名〜10名程度） | スマホ | 空き車両を見る／予約する／返却する（駐車場を選ぶ）／修理を頼む（修理の写真をつける）／車の写真を登録・変更する |
| 事務所・管理者 | PC | 今日の状況を見る／車検が近い車を見る／修理依頼を処理する／**車両の登録・修正・廃車（車の写真の登録・変更を含む）** |

### 名前の登録（日報アプリと同じ方式）
- 初回起動時に「あなたの名前を選んでください」画面。**名簿から選ぶだけ**（リストにない名前の入力欄は置かない。日報アプリと同じ）。
- 名前選びは日報アプリと同じ見た目：区分（自社／常駐協力／外注協力）ごとに見出しを付けて名前のボタンを3列に並べ、「名前で探す」の検索窓を置く。隠した人は出さない。
- 予約の「別の人にする」も同じ名前選びを使う。
- 選んだ名前は `localStorage` にそのスマホ用として保存。
- 予約・修理依頼の「使う人」「頼んだ人」は**自動で自分の名前**が入る。「別の人にする」で他の人も選べる。
- 一覧画面の右上に自分の名前が出て、押すと変更できる。

## 5. 画面仕様

### 5-1. スマホ版（現場向け）

画面の基本方針: **ぱっと見でごちゃつかない。文字を読まなくても色と大きさで分かる。押すボタンは大きく。**

#### ① 車両一覧（ホーム）
- 上段チップ: 全部 / 空き / 使用中（台数つき）
- 下段チップ: 全種類 / トラック / バン / 普通車（台数つき、上段と組み合わせて絞り込み）
- 車両カード（1台1枚）
  - 色帯: 緑=空き / オレンジ=使用中 / 赤=修理中。帯の右端に「使用中: 9/22〜9/26」または「空き: 次の予約 9/28〜」
  - 本体: 写真（なければ車のイラスト）／ナンバープレート風表示／車種／「田中さん → 東レ 定修」または「松前工場 にあります」
  - 車検が **30日以内** の車は、ナンバーの右に「🔔 車検 / あと18日」バッジを自動表示。期限超過は赤で「〇日超過」
- 下部タブ: 車両 / 車検 / 修理（未対応件数のバッジ）

#### ② 車両詳細
- 写真（大）＋ナンバー＋「📷 写真を登録」（写真がある車は「写真を変える」）。カメラかアルバムから選べる。送っている間は「送っています… ○%」。自動で縮小する
- 状態 / 使っている人 / 現場 / いつまで / 置いてある場所 / 修理内容 / 車検（年月日＋あと何日）
- ボタン: 空きなら「この車を予約する」、使用中なら「返却する」。どちらでも「修理を頼む」
- 今月のカレンダー（予約・使用中の日をオレンジ、今日を枠線）。次の予約があれば「次の予約：9/28〜 鈴木さん（熊本 浄化センター）」

#### ③ 予約
- いつからいつまで（日付2つ、初期値=今日）
- 使う人（自分の名前が入った状態。「別の人にする」で選択に切替）
- 行く現場（プルダウン。現場リストは Firestore の設定から。「その他」で自由入力も可）
- 「予約する」→ 完了画面「予約しました」
- **予約の重なりチェック**: 同じ車で日付が重なる予約があればエラー表示して登録しない
- 今日を含む期間なら即「使用中」に、未来なら「予約」として保存

#### ④ 返却
- 「どこに止めましたか？」→ 駐車場3つの大きなボタン（本社 / 松前工場 / 伊予工場 ※実名は設定から）
- 押した瞬間に返却完了。「返却しました／〇〇 に置いてある、と記録しました」

#### ⑤ 修理を頼む
- 症状チップ（複数選択）: エンジン警告灯 / 異音がする / タイヤ / ブレーキ / エアコン / 傷・へこみ / その他
- くわしく（任意テキスト）
- 写真をつける（任意、複数可）
- 「修理を頼む」→ 事務所に届く。頼んだ人は自分の名前
- 修理依頼が出た車は自動で **修理中** 扱いにはしない（走れる場合が多い）。事務所が「修理中にする」を押したときだけ修理中に変わる

#### ⑥ 車検タブ
- 全車を期限が近い順に一覧。右に「あと〇日」（30日以内オレンジ、超過は赤）

#### ⑦ 修理タブ
- 修理依頼の一覧（未対応 / 対応済み）

### 5-2. PC版ダッシュボード（事務所向け）

#### 上段（3枚横並び）
- **車検が近い車**（60日以内、近い順）
- **修理依頼**（未対応のみ。「対応済みにする」「修理中にする」「修理完了（空きに戻す）」ボタン）
- **この先の予約**（今日より後、日付順）

#### 下段: 全車両の表
- 状態ごとにグループ分け: 使用中 → 空き → 修理中（グループ見出しは色文字＋左の縦線。ベタ塗りはしない）
- 列: 状態 / 写真 / ナンバー / 車種 / 使っている人 / 現場（＋期間） / 置き場所 / 車検（あと〇日）
- 行をクリック → 車両の詳細・編集
- 右上に「＋ 車両を追加」

#### 車両の登録・修正・廃車（PC版のみ）
- **追加**: ナンバー（地域・分類番号・ひらがな・番号）/ 車種 / 種類（トラック・バン・普通車）/ 車検満了日 / 写真（任意）/ 通常の置き場所
- **修正**: 上記すべて（写真の変更を含む）＋車検更新後の期限入れ替え
- **廃車**: データは消さず `retired: true` にして一覧から非表示。表の下に「廃車済み（〇台）」の折りたたみがあり、そこから「戻す」もできる。予約・修理の履歴は残る
- **スマホ版には車両の登録・廃車の機能を置かない**（誤操作防止）。車の写真の登録・変更は、スマホ（車両詳細）とPC（車両の修正・追加）の両方でできる

#### 設定（PC版）
- 名簿（日報アプリと同じ形：名前・区分〔自社／常駐協力／外注協力〕・所属・表示するか）
  - 「日報の名簿から取り込む」ボタン：日報アプリ（yotsuba-nippo の Realtime Database `master/workers`）を読み、まだいない人だけ足す（日報で隠している人は隠した状態で入る。すでにいる人は変えない）
  - 1人ずつ「隠す／表示する」を切り替え（車を使わない人は隠す）。手で1人追加もできる。削除はしない
  - すでに入っている予約・修理の名前はそのまま残る（名前の文字で記録しているため）
- 現場リスト
- 駐車場リスト（3ヶ所）
- 車検通知の日数（初期値30日）

## 6. データ構造（Firestore）

```
vehicles/{vehicleId}
  plateArea: "愛媛"          // 地域
  plateClass: "300"          // 分類番号
  plateKana: "あ"
  plateNum: "12-34"
  kind: "ハイエース（バン）"  // 車種（自由入力）
  type: "バン"               // "トラック" | "バン" | "普通車"
  shakenDate: "2026-10-12"   // 車検満了日 YYYY-MM-DD
  photoUrl: "..."            // Storage のURL（なければ null）
  homeLot: "本社"            // 通常の置き場所
  currentLot: "本社"         // 今置いてある場所（返却時に更新）
  status: "free"             // "free" | "use" | "fix"（use は予約から自動計算でもよい）
  retired: false
  createdAt, updatedAt

reservations/{reservationId}
  vehicleId
  who: "田中"                // 使う人
  site: "東レ 定修"          // 現場
  from: "2026-09-22"
  to:   "2026-09-26"
  createdBy: "田中"          // 登録した人（自分 or 代理）
  returnedAt: null | timestamp
  returnedLot: null | "松前工場"
  createdAt

repairs/{repairId}
  vehicleId
  symptoms: ["異音がする","タイヤ"]
  memo: "右に曲がるときにゴトゴト鳴る"
  photoUrls: []
  reportedBy: "佐藤"
  status: "open"             // "open" | "in_repair" | "done"
  createdAt, doneAt

members/{memberId}             // 名簿（日報アプリの master/workers から取り込み）
  name: "芝"
  kubun: "自社"             // "自社" | "常駐協力" | "外注協力"（日報の古い「協力」は常駐協力に）
  shozoku: "よつば建設"
  active: true               // false = 隠す（スマホの名前選びに出さない）
  source: "nippo" | "manual"
  nippoKey: "w001"           // 日報側のキー（取り込んだ人だけ）
  createdAt, updatedAt

settings/app
  people: [...]                  // 旧：名前リスト。今は使わない（名前は名簿 members だけ）
  sites: ["東レ 定修","太陽石油",...]
  lots: ["本社","松前工場","伊予工場"]
  shakenAlertDays: 30

inspections/{id}                 // 車検の記録（PCの「車検に出す」「車検から戻す」）。今は画面に出さない
  vehicleId, outDate, expectedBack, backDate
  oldShakenDate, newShakenDate     // 前の満了日・新しい満了日
  outBy, backBy, returnedLot       // 操作した人・戻した置き場所
  outAt, backAt
// vehicles の inspection: { id, from, until } があいだは「車検中」（戻すと null）

settings/notify                  // 通知を届ける人（PC ⚙設定 → 通知）。最初は全員オフ
  shaken: ["田中",...]  due: [...]  overdue: [...]  repair: [...]

notifyPrefs/{名前をURLエンコードしたもの}   // 本人がスマホでオフにした通知（初期はすべてオン）
  name: "田中"
  off: ["due"]

pushTokens/{通知トークン}          // 通知を許可した端末。1人が複数でもよい。無効になったら Functions が消す
  name: "田中"                     // その端末の localStorage の名前
  platform: "ios" | "android" | "pc"
  updatedAt

notifyLog/{通知のキー}             // 送った記録（Functions だけが使う）。同じ人に2回送らない
  sentTo: ["田中",...]
```

### 状態の決め方
- `retired` → 表示しない
- `inspection` がある → **車検中**（紫 #7A5BB5）。出した日〜戻り予定日（なければ今日）に重なる予約はできない
- 修理 `status == "in_repair"` の依頼がある → **修理中**
- 今日を含む予約（from ≤ 今日 ≤ to）で `returnedAt` が空 → **使用中**
- それ以外 → **空き**

## 7. 実装の段階分け（消防車アプリと同じく段階ごとに実機確認）

| 段階 | 内容 | 完了条件 |

## 8. デザイン指定

- 色: ヘッダー `#2C4966`（鋼の紺）、空き `#2E9E5B`、使用中 `#E08A1E`、修理 `#C8443A`、背景 `#EEF0EC`

## 9. やらないこと（今回のスコープ外）

- GPS・位置追跡・地図表示
- LINE／メール通知（通知はプッシュ通知のみ。下の「プッシュ通知」を参照）

### プッシュ通知（2026-10 追加）
- Firebase Cloud Messaging（Web Push）＋ Cloud Functions（`functions/`、`firebase deploy --only functions`）
- 届く条件：PCの「⚙設定 → 通知」でオン かつ 本人がスマホの「🔔 通知」でオフにしていない かつ 通知を許可した端末がある
- 時刻はすべて日本時間

| 通知 | いつ | 誰に |
|---|---|---|
| 車検 | 満了日まで「車検の通知」日数以内になった朝8時（満了日ごとに1回） | オンの人（全車両） |
| 返却予定日 | 予約の最終日の17時、まだ返却していなければ | 使う人本人だけ |
| 返却遅れ | 最終日の翌朝9時、まだ返却していなければ | 使う人本人だけ |
| 修理依頼 | 登録されたらすぐ | オンの人（頼んだ本人を除く） |

- サンプルの車・予約・修理（sample: true）、廃車・一時的に隠した車（車検のみ）には送らない
- 公開鍵（VAPID）は `firebase-config.js` の `VAPID_KEY`。空のあいだは通知の機能を出さない
- 走行距離・給油・ETC等の記録
- 複数会社対応・ログイン管理
